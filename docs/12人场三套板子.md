# 12 人场 · 三套板子（结构级创新版）

三张海报：`板子壹-公开答辩.png` / `板子贰-后门植入.png` / `板子叁-模块边界.png`。

---

## 先说清楚：之前那三套是不够的

第一版三套（代码审查会 / 上线倒计时 / 技术债交易）本质上是**换皮**：把网易的猎人改成测试老兵、白痴改成实习生、警徽改成合并令，骨架还是那副骨架 —— 夜里狼刀一个、白天投一个、预言家验人。

**换名字不叫创新。** 真要不一样，就得动规则骨架本身。

所以我挑了三件狼人杀里从来没被改过的事，一套改一件：

| | 板子壹 | 板子贰 | 板子叁 |
|---|---|---|---|
| 名字 | **公开答辩** | **后门植入** | **模块边界** |
| 改掉哪条铁律 | 被投出的人只能等死 | 阵营从头到尾不会变 | 所有人都能看见全场事 |
| 新机制 | 申辩额度（翻牌免死） | 植入后门（票不听自己使唤） | 三个模块（信息隔离） |
| 一句话 | 被投出的人还能翻盘 | 死人不一定是死人 | 你只看得见自己那一层 |

底层不变的部分：12 人 = 4 神 4 民 4 卧；所有技能必须答对题才生效；共用一枚**合并令**（见文末）。

## 板子壹 ·「公开答辩」

**改淘汰规则 —— 被投出的人还能翻盘**

### 阵营
- **好人 · 神职 4**：代码审核员 / 豆包 / 测试老兵 / 冻结管理员
- **好人 · 平民 4**：普通程序员 ×4
- **卧底 4**：Bug 制造者 ×3 / 零日漏洞 ×1

| 角色 | 技能 | 答题 |
|---|---|---|
| 代码审核员 | 每晚核验一人身份，答对即知阵营 | 代码审查 |
| 豆包 | 好包救人 / 孬包毒人，全局各一次 | 调试排错 |
| 测试老兵 | 出局时提交复现报告，指名带走一人 | Bug 识别 |
| 冻结管理员 | 每晚冻结一人，他白天不能发言，但仍可投票 | 编程规范 |
| 普通程序员 ×4 | 无技能 | — |
| Bug 制造者 ×3 | 每晚共同暗害一人，答对才成立；白天可自爆，全局一次 | Bug 识别 |
| 零日漏洞 | 白天公开披露＝自爆并带走一人，全局一次 | Bug 识别 |

### 核心机制 · 申辩额度（全场 2 次）

投票结束、票数最高的人出局**之前**，他可以举手申辩，现场答一道该轮对应的题：

- **答对** → 当众**翻牌免死**，本轮无人出局，他的身份牌向全场公开
- **答错** → 立即出局，且**不留遗言**
- **额度全场共享，共 2 次** —— 用掉一次就少一次，不会再有

**为什么狼不敢用**：答对就要翻牌。翻牌等于把自己交出去。所以这个机制实际上是**好人专属的容错**，狼只能靠"骗别人把额度用光"来获益。

**为什么是 2 次不是每人一次**：额度是公共的，就有"这票值不值得动用额度"的博弈 —— 投一个明显的好人，好人会犹豫要不要救；投一个可能是狼的人，救下来还翻牌，直接吃掉一个狼位。**额度用在哪，本身就是要辩的东西。**

## 板子贰 ·「后门植入」

**改阵营规则 —— 死人不一定是死人**

### 阵营
- **好人 · 神职 4**：代码审核员 / 豆包 / 学术监督员 / 冻结管理员
- **好人 · 平民 4**：普通程序员 ×4
- **卧底 4**：Bug 制造者 ×3 / 幽灵提交 ×1

| 角色 | 技能 | 答题 |
|---|---|---|
| 代码审核员 | 每晚核验一人身份，答对即知阵营 | 代码审查 |
| 豆包 | 好包救人 / 孬包毒人，全局各一次 | 调试排错 |
| 学术监督员 | 每晚护一人，不可连守；免疫投票出局 | 编程规范 |
| 冻结管理员 | 每晚冻结一人，他白天不能发言，但仍可投票 | 编程规范 |
| Bug 制造者 ×3 | 每晚共同暗害一人，答对才成立 | Bug 识别 |
| **幽灵提交** | 被核验时显示为好人，不参与夜间选刀 | — |

### 核心机制 · 后门植入（全局 1 次，第 2 夜起）

狼可以**放弃当晚的刀**，改为对一名玩家植入后门：

- 被植入者**不死**，照常发言、照常投票
- 但从次日起，**他的票自动计入狼方**（系统计票时把他的票算给狼指定的目标）
- **他被核验时显示为狼**（因为已经叛变）
- **他自己知道**，但也仅限他自己

于是产生了狼人杀里从来没有的局面：**场上多了一个活着的、知道自己是好人、却管不住自己那张票的人。**

他说出来 → 狼当晚必定灭口。他不说 → 好人会因为他的票而误判。

**平衡**：狼少一刀换一个内应，净收益约 +2 票差（少死一个好人 ≈ +1，多一张狼票 ≈ +1）。所以全局只有 1 次、且第 2 夜起才能用，避免开局就崩。

## 板子叁 ·「模块边界」

**改信息规则 —— 你只看得见自己那一层**

### 阵营
12 人分成三个模块，每模块 4 人：**前端 / 后端 / 数据**（现场按桌分，一桌一个模块）。

- **好人 · 神职 4**：代码审核员 / 豆包 / 测试老兵 / CI 哨兵
- **好人 · 平民 4**：普通程序员 ×4
- **卧底 4**：Bug 制造者 ×3 / 影子分支 ×1

| 角色 | 技能 | 答题 |
|---|---|---|
| 代码审核员 | 每晚验一人，**但只能验同模块的人** | 代码审查 |
| 豆包 | 好包救人 / 孬包毒人，全局各一次 | 调试排错 |
| 测试老兵 | 出局时提交复现报告，指名带走一人 | Bug 识别 |
| **CI 哨兵** | 昨夜死者与你同模块时，天亮公开「红灯」 | 编程规范 |
| Bug 制造者 ×3 | **只能暗害与自己同模块的人**，答对才成立 | Bug 识别 |
| **影子分支** | 跨越模块动手，**每 2 晚只能动一次** | 调试排错 |

### 核心机制 · 三个模块

- **狼只能在同模块内下手** → 狼的杀伤范围被他的座位限制，狼必须分布在不同模块才能覆盖全场
- **验人也被限制在同模块** → 好人拿到的也只是碎片
- **白天先分组讨论 5 分钟，再合场 10 分钟** → 每个模块只知道自己的事

**为什么这样反而更好玩**：狼的分布决定了哪些模块"安全"。如果连续三天只有后端死人，那么后端那几个人就一定有问题 —— 这是纯靠**空间推理**得出的结论，跟发言水平无关。同时狼也能反过来利用：故意在某个模块连杀，把好人的注意力钉死在那儿。

**主持人负担**：需要按桌分组，每桌 4 人。12 人座次不好凑的话，可以先按抽签排好再开机。

## 合并令 · CODEOWNERS 令牌（三套共用）

替代「警徽」。名字取自 GitHub 的真实机制：仓库里谁的名字写在 `CODEOWNERS` 文件里，谁就能批准或拒绝合并。持有者叫**代码所有者**。

| 环节 | 规则 |
|---|---|
| **产生** | 第 1 天天亮后上警，上警者各 60 秒拉票，中途可退水（退水即失去投票权） |
| **选举** | 只有未上警的存活玩家投票；**平票直接作废，不重投** |
| **票权** | 持有者一票算 **1.5 票**（内部 2 分制：普通票 2 分、持有者 3 分） |
| **定序** | 每天发言开始前，持有者决定从几号开始、顺时针或逆时针 |
| **交接** | 持有者出局时，移交给场上任意存活玩家，**或当场撕毁** —— 本局不再有合并令 |

**为什么平票就撕**：12 人场时间紧，选警长重投两轮要多拖十分钟；而且"选不出合并令"本身就是信息 —— 说明场上没人能带节奏。

**主持人提醒**：第一天如果没人上警，就直接撕掉 —— 这一局的话语权会落到最会带节奏的那个人手里，通常不是好人。

## 附：被淘汰的旧三套

`docs/` 里已不再提供第一版（代码审查会 / 上线倒计时 / 技术债交易）。它们的机制（Scan 报告、强制上线、技术债）都是好想法，但都建立在"换皮"的角色上，骨架没动。其中**「技术债」可单独作为三套共用的可选附加规则**：白天任何时候，任何玩家都可以借一次技术债，答对换「本轮免疫投票」，答错当众公开阵营 —— 狼也能借。
