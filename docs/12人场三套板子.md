# 12 人场 · 三套板子（正式版 · 已校准强度）

三张海报见同目录 `板子壹-代码审查会.png` / `板子贰-上线倒计时.png` / `板子叁-技术债交易.png`。

**三套共用底层规则**：12 人 = 4 神 + 4 民 + 4 卧；白天发言 → 投票 → 出局结算；
共用同一枚**「合并令」**（替代网易的警徽）与同一条铁律：**所有技能都要答对题才生效，答错当场作废。**

三套的区别只有一个：

| | 板子壹 | 板子贰 | 板子叁 |
|---|---|---|---|
| 名字 | 代码审查会 | 上线倒计时 | 技术债交易 |
| 赌什么 | **信息的可信度** | **时间** | **风险偏好** |
| 一句话 | 每一条线索都可能是假的 | 带病发布就是输 | 答错一题当众剥光 |
| 适合 | 第一次开 12 人场 | 节奏太慢、爱拖的班 | 老手局 |

## 零、强度是怎么算的（这一节最重要）

三个板子都按同一个尺子校过：**好人每夜能拿到几条"指向具体人"的信息，卧底每夜能制造几次死亡。**

| | 好人信息位 | 好人保护位 | 狼的刀数 | 狼的额外能力 |
|---|---|---|---|---|
| 板子壹 | 1（代码审核员） | 1（豆包）+ 控场（冻结） | 3 | 自爆带人 ×1 |
| 板子贰 | 1 | 2（豆包 + 学术监督员） | 3 | 带人 ×1 + 时限压力 |
| 板子叁 | 1（**而且会被骗**） | 2（豆包 + 结对伙伴） | **2** | 偷看身份（每 2 晚 1 次） |

**核心原则：好人永远只有一个真验人位。** 第二个"验人类"技能一旦出现，12 人 4 狼的局面会在第 3 晚就被验穿——狼没有生存空间，游戏提前结束，参与者体验极差。

所以三套里所有"额外信息"都做了两件事之一：**要么不是指向具体人的**（板子壹的 Scan 是范围报告），**要么狼自己也有**（板子叁的偷看）。

## 板子壹 ·「代码审查会」

**信息战 —— 每一条线索都可能是假的**

### 阵营
- **好人 · 神职 4**：代码审核员 / 豆包 / 测试老兵 / **冻结管理员**
- **好人 · 平民 4**：普通程序员 ×4
- **卧底 4**：Bug 制造者 ×3 / **零日漏洞** ×1

> 最初这里放的是「静态扫描器」（每晚指定一人、次日公开扫描结果）。**那就是第二个预言家**——12 人局有两位验人位，狼在第 3 晚就被验穿，游戏直接结束。已删掉，改成公共机制，见下。

### 角色
| 角色 | 技能 | 答题 |
|---|---|---|
| 代码审核员 | 每晚核验一人身份，答对即知阵营 | 代码审查 |
| 豆包 | 好包救人 / 孬包毒人，全局各一次 | 调试排错 |
| 测试老兵 | 出局时提交复现报告，指名带走一人 | Bug 识别 |
| **冻结管理员** | 每晚冻结一人，他白天不能发言，但仍可投票 | 编程规范 |
| 普通程序员 ×4 | 无技能，靠发言与投票站边 | — |
| Bug 制造者 ×3 | 每晚共同暗害一人，答对才成立；白天可自爆，全局一次 | Bug 识别 |
| **零日漏洞** | 白天公开披露＝自爆并带走一人，全局一次 | Bug 识别 |

### 创新机制 · 每日 Scan 报告（30% 假报告）

天亮时系统**随机抽 2 名存活玩家**，公布「其中恰有 1 人告警」或「两人都干净」，
**整条报告有 30% 概率是假的。**

它最多把范围从 12 缩到 2，而且可能是错的 —— **给的是话题，不是结论。**

关键在于它是**公共的**：好人能引用，狼也能引用。一条假报告落在好人头上，狼会立刻拿着它带节奏。所以"这条报告可不可信"本身就成了要辩的东西。

## 板子贰 ·「上线倒计时」

**时间压力 —— 带病发布就是输**

### 阵营
- **好人 · 神职 4**：代码审核员 / 豆包 / 学术监督员 / **发布经理**
- **好人 · 平民 4**：普通程序员 ×4
- **卧底 4**：Bug 制造者 ×3 / **遗留系统** ×1

### 角色
| 角色 | 技能 | 答题 |
|---|---|---|
| 代码审核员 | 每晚核验一人身份，答对即知阵营 | 代码审查 |
| 豆包 | 好包救人 / 孬包毒人，全局各一次 | 调试排错 |
| 学术监督员 | 每晚护一人，不可连守；免疫投票出局 | 编程规范 |
| **发布经理** | 全局一次「强制上线」：跳过发言直接投票 | 代码审查 |
| 普通程序员 ×4 | 无技能，但每个人都有时间压力 | — |
| Bug 制造者 ×3 | 每晚共同暗害一人，答对才成立 | Bug 识别 |
| **遗留系统** | 出局时技术债引爆，带走一人 | Bug 识别 |

### 创新机制 · 第 5 天强制上线

**第 5 天结束时卧底仍未全灭，卧底阵营直接获胜** —— 项目要上线，Bug 只能带病发布。

发布经理的「强制上线」会立刻结束当天发言、进入投票，且本轮**所有人必须投出人，禁止弃票**。

天数可在设置页调到 4–6。

> **为什么是 5 天不是 4 天**：12 人 4 狼的常规局通常要打 5–6 天。卡 4 天等于直接判好人输——好人一夜只有一条验人信息，4 天内投出 4 个狼在数学上几乎不可能。5 天是"紧但可赢"的临界点。

## 板子叁 ·「技术债交易」

**风险偏好 —— 答错一题当众剥光**

### 阵营
- **好人 · 神职 4**：代码审核员 / 豆包 / 测试老兵 / **结对伙伴**
- **好人 · 平民 4**：普通程序员 ×4
- **卧底 4**：Bug 制造者 ×2 / **幽灵提交** ×1 / **影子分支** ×1

### 角色
| 角色 | 技能 | 答题 |
|---|---|---|
| 代码审核员 | 每晚核验一人身份，答对即知阵营 | 代码审查 |
| 豆包 | 好包救人 / 孬包毒人，全局各一次 | 调试排错 |
| 测试老兵 | 出局时提交复现报告，指名带走一人 | Bug 识别 |
| **结对伙伴** | 每晚与一人结对，他免疫；你出局他同死 | 编程规范 |
| 普通程序员 ×4 | 无技能，但可以借技术债翻盘 | — |
| Bug 制造者 ×2 | **全场只有这两把刀**；队友里还藏着一个假好人 | Bug 识别 |
| **幽灵提交** | 被核验时显示为好人，且不知队友是谁；**不参与夜间** | — |
| **影子分支** | **每 2 晚**偷看一人具体身份，**不参与选刀** | 调试排错 |

### 创新机制 · 技术债（每人一次，任何人都能借）

白天任何时候，**任何玩家**都可以借一次技术债：

- **答对一题** → 换取「本轮免疫投票」或「查看某人昨夜是否被保护」
- **答错** → 当众公开自己的阵营

**狼也能借** —— 所以"他借债了"不证明他是好人。

> **为什么限制这么狠**：这一套的狼有假身份又有偷看，信息本来就占优。如果不把刀数压到 2 把、不给影子分支每晚都看，好人必输。**技术债是给好人补的那口气。**

## 合并令 · CODEOWNERS 令牌

**这是替代「警徽」的东西。** 名字取自 GitHub 的真实机制：仓库里谁的名字写在 `CODEOWNERS` 文件里，谁就能批准或拒绝合并 —— 谁有合并权，谁就是这个项目的实际话事人。

持有合并令的人叫**代码所有者**。

| 环节 | 规则 |
|---|---|
| **产生** | 第 1 天天亮后上警，上警者各 60 秒拉票，中途可退水（退水即失去投票权） |
| **选举** | 只有未上警的存活玩家投票；**平票直接作废，不重投** |
| **票权** | 持有者一票算 **1.5 票**（内部 2 分制：普通票 2 分、持有者 3 分） |
| **定序** | 每天发言开始前，持有者决定从几号开始、顺时针或逆时针 |
| **交接** | 持有者出局时，移交给场上任意存活玩家，**或当场撕毁** —— 本局不再有合并令 |

**为什么平票就撕**：网易版平票是重投，但 12 人场时间紧，卡在选警长上重投两轮要多拖十分钟。而且"选不出合并令"本身就是信息 —— 说明场上没人能带节奏，后面投票会更散。

**主持人提醒**：第一天如果没人上警，就直接撕掉合并令 —— 这一局的话语权会落到最会带节奏的那个人手里，通常不是好人。

> ★ 移交给谁，是这局最好看的一句话 —— 因为接的人不一定是好人。
