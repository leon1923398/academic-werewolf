# 学术狼人杀 · 主持人控制台

「以辩促思，以游促学」——把编程规范、代码审查、调试排错、Bug 识别塞进狼人杀的技能位里。
**一台电脑、一个投影、六个人，双击 `index.html` 就能开一局。** 不联网、不装软件、不需要每人一部手机。

---

## 一、为什么做成"主持人单机版"

市面上狼人杀 App 都是联网房间制，现场会死在三件事上：教室 Wi-Fi 不稳、不可能人人装 App、开局前 20 分钟全花在教人注册上。

所以这一版把**主持人当成游戏服务器**：身份靠"把设备依次递给对应玩家，点开自己的座位卡看三秒、按「我已记住」自动遮屏"，全程不需要第二台设备。投影上大家看到的是公开信息（座位、票型、遗言、进度），私密信息只出现在递过去的那几秒里。

代价是：**主持人必须按界面上写的话念**。界面已经替你把该说的话写好了（"请闭眼"、"请学术监督员睁眼"），照着念就行，不会串词。

## 二、开一局

1. 双击 `index.html`（Chrome / Edge，全屏 F11）。
2. 封面 →「开始」。
3. **设置页**：人数选 **6**（默认就是 6 人），下面六个角色的数量自动填好；答题时间默认 30 秒，够用就别动。
4. **发牌页**：把设备递给玩家 1，他点自己的座位 → 弹出身份卡 →「我已记住」→ 遮屏 → 递给下一个人。**看过的座位会锁死，点不开**（防止后面的人偷看前面的人）。
5. 全部看完 →「开始游戏」。

之后就是一条竖着走完的路：**第 N 夜 → 天亮 → 轮流发言 → 匿名投票 → 结算 / 下一夜**。

### 夜晚怎么主持

界面会依次让你点：学术监督员 → Bug 制造者（含搬运工）→ 豆包 → 代码审核员。
每一步都要**把设备递过去，让当事人自己点**，点完就弹一道题：

- 答对了 → 技能生效（守卫的防火墙设上、暗杀成功、药水喂出去、身份核验到结果）。
- 答错了 → **技能当场作废**，这一晚白过。

倒计时 30 秒，超时按答错算。这就是"以辩促思"的落点：**你能不能说清这个规范/这个 Bug，直接决定你今晚能不能出手。**

如果某个角色已经出局，界面会显示"已出局，本步骤跳过"，你不用管。

### 白天怎么主持

- **轮流发言**：界面按座位顺序点名，每人 90 秒（可跳过）。
- 发言期间 **Bug 制造者可以随时发动「病毒植入」（自爆）**：点按钮 → 答题 → 答对直接入夜、跳过本轮投票；答错继续发言。**全局只有一次，答错也算用掉。**
- **匿名投票**：叫大家依次报出怀疑对象，主持人**按唱票顺序点座位**，点一次记一票，票数实时隐藏。点错了按「撤销一票」。
- **揭晓**：得票最高者出局。**如果他是被学术监督员挡过的人，本轮投票无效，无人出局。**

### 结束

- 卧底全部出局 → 好人胜。
- 卧底人数 ≥ 好人 → 卧底胜。
- 结算页会自动给出：全员身份揭晓、**逐题战报**（谁在第几轮答的哪道题、对错、解析）、完整事件时间线。
- 点「导出战报」下载 `学术狼人杀战报_日期.md`，可以直接粘进活动总结，也可以作为学时认定的过程材料。

## 三、六人局配置（默认）

| 阵营 | 角色 | 人数 | 技能 |
| --- | --- | --- | --- |
| 好人 | 普通程序员 | 1 | 无技能，靠嘴 |
| 好人 | 代码审核员 | 1 | 每晚核验一人身份，答题成功才生效 |
| 好人 | 学术监督员 | 1 | 每晚护一人，答题成功才生效；不可连续两晚护同一人 |
| 好人 | 豆包 | 1 | 好包救人 / 孬包毒人，全局各一次，每晚只能用一种 |
| 卧底 | Bug 制造者 | 1 | 每夜暗害一人，答题成功才成立 |
| 卧底 | 代码搬运工 | 1 | 无夜间能力，白天带节奏、洗白队友、诬陷好人 |

**好人 4 / 卧底 2。** 选这个配置的理由：6 人是这个活动最现实的最小规模，而策划书里的六个角色正好一人一个全上场——一场就把整套设计演完，评分表上"角色覆盖完整"这一栏没有缺口。

人多了（8/10/12/14）在设置页直接选，角色数量会自动配平，多出来的位置补"普通程序员"。

## 四、和策划书原文的四处差异（都是有意的，可以改回去）

1. **学术监督员的防火墙只挡投票，不挡夜里的暗害。**
   策划书原文写的是"该玩家本轮免疫投票出局"，我按字面实现了。标准狼人杀的守卫是挡夜刀的，但那样 6 人局好人太强。
   设置页有 `守卫范围` 开关，想改成"夜刀也挡"就切到 `both`。

2. **孬包（毒药）在夜间结算，不在白天投票前。**
   策划书把毒药放在白天，实际主持会乱：夜里死了人、天亮公布、然后又要追溯昨夜谁被毒——中间隔了一次公布，信息顺序对不上。改成夜里连喂，天亮一起公布，逻辑才顺。

3. **自爆失败不消耗发言，但消耗次数。**
   策划书说"失败继续发言"，没说次数怎么算。我的处理是：**失败也消耗那唯一一次**——否则一个 Bug 制造者可以每轮都点一次自爆刷题，把 60 道题库刷穿，这就不是在比推理了。

4. **卧底判定严格按"全部出局"。**
   我一度加了"主卧底全灭就算好人胜"的快速结束规则，但那样 6 人局只要投中一个 Bug 制造者就立刻结束，搬运工成了摆设，和策划书"卧底全部出局"的原文也不符。已回退。

## 五、题库

`questions.js` 里 60 道题，四类各 15 道，和四个技能一一对应：

| 类别 | 对应技能 | 考什么 |
| --- | --- | --- |
| 编程规范 `spec` | 学术监督员 · 防火墙 | 命名、魔法数字、空 catch、密钥入库、可变默认参数 |
| 代码审查 `review` | 代码审核员 · 身份核验 | SQL 注入、资源泄漏、MD5 存密码、索引失效、N+1、并发容器 |
| 调试排错 `debug` | 豆包 · 双药 | 读异常栈、git bisect、条件断点、死锁、时区、编码乱码 |
| Bug 识别 `bug` | Bug 制造者 · 暗杀 | 越界、除零、use-after-free、闭包陷阱、比较器违约、check-then-act |

同一局里不会重复出题（用完一轮才会重置）。

**要换题**：直接编辑 `questions.js`，格式是

```js
{ q: '题干', code: '要展示的代码片段（可省略）', opts: ['A', 'B', 'C', 'D'], ans: 1, why: '解析' }
```

`ans` 是正确选项的下标（从 0 开始）。加多少题都行，脚本会自动适应。

## 六、出问题时

- **投影看不清**：浏览器放大到 125%~150%，座位板会自动重排。
- **点错座位**：投票界面有「撤销一票」；夜晚步骤点错可直接重新点（会覆盖，不叠加）。
- **有人偷看了别人身份**：发牌页已锁死看过的座位，理论上做不到。真发生了就重开一局——设置页点「重新开始」。
- **中途要停**：直接关掉页面，战报导出会丢。建议一局打完再退。
- **想复盘**：结算页就是复盘页，逐题战报连解析都列好了。
